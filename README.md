# 个人工作台

一个运行在本机的个人效率工作台，采用左侧导航、右侧内容区的简约控制台布局。它把高频使用的提示词、网址、API Key 和本机软件快捷方式集中到一个 `127.0.0.1` 页面中。

当前版本：`v1.3.0`

> 重要：本项目是本地优先应用，不提供账户、云同步或远程数据库。工作区数据保存在项目的 `.workbench-data/`，修改绑定端口不会切换或清空配置。

## 从 GitHub Release 安装

1. 从 Releases 下载 `personal-workbench-v1.3.0-windows.zip`。
2. 将 ZIP 完整解压到有写入权限的固定目录，例如 `D:\PersonalWorkbench`。不要直接在压缩包内运行，也不要放在会自动清理的临时目录。
3. 安装 Node.js 20.19+ 或 22.12+，安装时保留 npm。
4. 双击 `install-workbench.cmd`。首次安装会显示一个 CMD 窗口用于展示 npm 安装进度，完成后会静默启动工作台并打开浏览器。
5. 后续启动或重启可双击 `start.cmd`，不会显示 CMD 窗口；需要停止服务时双击 `end.cmd`。

默认地址是 <http://127.0.0.1:5180/>。如果在设置中修改端口，服务会静默重启，当前标签页随后跳转到新地址。

> Release ZIP 不包含 `.workbench-data`、个人书籍、快捷方式、运行日志或任何 API Key 数据。升级前请备份原安装目录中的 `.workbench-data`，覆盖程序文件时保留该目录。

## 快速开始

### 环境要求

- Windows（应用启动器只支持 Windows）。
- Node.js 20.19+，或 Node.js 22.12+。
- 可用的现代浏览器，且浏览器允许当前页面使用 Web Crypto 和剪贴板功能。

### 安装和启动

开发者也可以在项目根目录执行：

```powershell
npm install
npm run dev
```

默认打开：<http://127.0.0.1:5180/>

如果已经在设置页修改过端口，请打开 `http://127.0.0.1:<已配置端口>/`。本地服务需要保持运行；应用启动器、端口设置和开机自启动接口由 Vite 服务提供，直接双击 `index.html` 无法使用这些功能。

### 构建检查

```powershell
npm run build
```

构建产物在 `dist/`，该目录已被 Git 忽略。生产预览可以执行：

```powershell
npm run preview
```

预览服务使用相同的本机端口配置，默认访问：<http://127.0.0.1:5180/>。

## 第一次使用

第一次打开页面时，需要创建一个工作区并设置至少 8 位的独立密码。以后刷新页面或重新打开页面，都需要输入密码解锁对应工作区。

密码明文不会写入浏览器或本地配置文件。当前版本没有密码找回或重置流程：忘记密码后，原有 API Key 无法解密。工作区配置保存在 `.workbench-data/workbench.json`，清除浏览器站点数据不会删除已经迁移的工作区数据。

### 设置

- 侧边栏顶部的收起按钮可以折叠/展开侧边栏；窄窗口下仍使用顶部菜单按钮打开抽屉。
- 设置页采用标准的左侧分类、右侧内容排版，分类包括“工作区”“密码与安全”“数据管理”“启动设置”“语言”。
- “工作区”可以修改当前工作区名称；名称不能为空，也不能与其他工作区重名。
- “密码与安全”可以修改工作区密码。必须输入当前密码，新密码至少 8 位；已有 API Key 会自动使用新密码派生的密钥重新加密。
- 设置页可以导出当前工作区配置。配置内容使用当前工作区的 AES-256-GCM 密钥加密，导出的 JSON 不包含密码明文或 API Key 明文。
- 在新设备的创建工作区页面选择“导入已有配置”，或在已有工作区的设置页选择“导入配置”。导入时必须输入原工作区密码；配置名重复会询问是否覆盖，并提示工作区密码也会被覆盖。
- “启动设置”可以修改本地绑定端口，范围是 `1024-65535`。保存后服务会静默重启并跳转到新地址，目标端口不能被其他程序占用。
- 设置页的“开机自启动”会在 Windows 启动目录创建本地服务项。启用后，登录 Windows 会按当前配置端口启动 Vite 服务。
- 设置页的“语言”可以在中文、English、日本語之间切换，界面偏好保存在当前浏览器本机；工作区数据不会被翻译或修改。
- 收起侧边栏时，个人工作区切换卡片会隐藏，展开按钮与导航按钮保持一致的尺寸、间距并居中显示。

## 功能和使用方法

### 工作区

工作台支持多个彼此隔离的本地工作区。首次打开时创建第一个工作区并设置密码；点击左侧顶部的工作区卡片可以新建或切换工作区。每个工作区都有独立密码，登录页输入任意已配置工作区的密码，会直接进入对应工作区；从当前工作区切换到其他工作区时需要输入目标工作区密码。

提示词、网址收藏、API Keys、书籍元数据、书籍文件和应用快捷方式都会按工作区分别保存，新工作区默认为空，不会读取其他工作区的数据。

### 概述

打开工作台后默认进入“概述”。左侧导航分为“工作台”“资源中心”和“工具”，右侧显示当前模块内容。设置页位于侧边栏底部，用于管理工作区名称、密码、配置数据、绑定端口和开机启动。

概述页顶部显示当前电脑用户名、根据时间段变化的问候语、实时电脑时间和日期；下方提供提示词库、网址收藏、API Keys、应用启动器、个人书库和番茄钟快捷入口，并显示最近使用的提示词。工具快捷入口旁的“关闭服务”按钮可以停止当前本地服务，服务停止后使用 `start.cmd` 或 `end.cmd` 重新控制。

### 番茄钟

1. 点击左侧“番茄钟”进入专注计时工具。
2. 可以选择 15、25、45 或 60 分钟预设，也可以输入自定义整数时长。
3. 自定义时长支持“分钟”和“小时”单位；分钟上下按钮每次调整 10，小时上下按钮每次调整 1，但手动输入允许任意不超过 24 小时的整数分钟值，例如 13 分钟。
4. 点击“开始专注”开始计时，可以暂停、继续或重置。计时状态只保存在当前页面会话中，不写入工作区数据。

### 提示词库

1. 点击左侧“提示词库”。
2. 点击“新建提示词”，填写标题和内容；在标签输入框中输入内容后按 `Enter` 或逗号添加标签。
3. 保存后，可以通过搜索框匹配标题、内容和标签，也可以点击标签筛选。
4. 每张提示词卡片右上角的三点菜单包含“复制”“编辑”“删除”。复制只复制提示词内容。
5. 每页显示 6 条记录。记录超过 6 条后，底部会显示上一页、页码和下一页。

首次使用时，内置 24 条示例提示词；已有浏览器数据会保留，并按标题补齐缺少的示例数据。

### 网址收藏

1. 点击左侧“网址收藏”，再点击“新建网址”。
2. 填写标题、网址、备注和标签。网址必须以 `http://` 或 `https://` 开头。
3. 每条记录可以直接打开、编辑或删除。
4. 每页显示 6 条记录，超过 6 条后显示分页。

首次使用时会提供 20 条“分页测试网址”，它们会与已有收藏按标题合并，不会覆盖同名的本地记录。这些地址使用 `example.com`，主要用于检查分页布局。

### API Keys

点击左侧“API Keys”，每条记录包含以下字段：

| 字段 | 存储方式 | 使用说明 |
| --- | --- | --- |
| 名称 | 明文 | 用于识别记录，例如 `OpenAI Production` |
| 服务商 | 明文 | 例如 OpenAI、Anthropic 或自建服务 |
| API Key | AES-256-GCM 密文 | 保存时加密，列表默认掩码 |
| 请求地址 | 明文 | 必须是 `http://` 或 `https://` 地址 |

使用步骤：

1. 点击“添加 API Key”，填写四个字段并点击“加密保存”。
2. 列表中点击眼睛按钮，可以在当前已解锁页面中显示或隐藏 API Key。
3. 编辑记录时，页面会在内存中解密原 Key；重新保存时会使用新的随机 IV 重新加密。
4. 每页显示 6 条记录，超过 6 条后显示分页。

只有 API Key 字段加密，名称、服务商和请求地址按设计以明文保存，便于列表展示和识别。

### 个人书库和阅读器

个人书库用于导入并阅读本机电子书，不是阅读状态记录工具。

1. 点击左侧“个人书库”，点击右上角“导入书籍”。
2. 选择本机的 `PDF`、`EPUB`、`TXT`、`Markdown` 或 `HTML` 文件。
3. 文件会保存到项目的 `.workbench-data/workspaces/{workspaceId}/books/`，不会上传网络；书库保存书名、文件名、类型、大小、可选的作者/分类信息和上次阅读位置。
4. 点击书籍卡片上的“阅读”进入右侧主内容区的阅读页。左上角“返回书库”返回列表；PDF 使用浏览器内置预览，EPUB 使用内置分页阅读器，TXT/Markdown 使用本地文本阅读视图，HTML 使用沙箱 iframe 阅读。
5. EPUB 阅读页底部提供“上一页”和“下一页”按钮；每次翻页会保存当前 CFI，重新打开时直接恢复到上次页面。TXT/Markdown 会保存滚动位置，PDF/HTML 使用浏览器阅读视图。当前版本不计算或显示阅读百分比。
6. 可搜索书名、作者、分类和文件名，也可以按文件类型筛选。
7. 可以编辑书名、作者和分类；删除书籍会同时删除 `.workbench-data` 中对应的本地文件副本。
8. 每页显示 6 本书，超过 6 本后显示分页。

当前版本不支持直接导入 `.mobi`、`.azw` 等格式；请先转换为 PDF 或 EPUB。清除浏览器站点数据不会删除已经迁移或新导入的书籍文件；备份或迁移项目时应完整保留 `.workbench-data/`。

### 应用启动器

应用启动器用于启动本机软件，不会启动远程程序：

1. 确认已经通过 `restart-workbench.vbs`、`npm run dev` 或 `npm run preview` 启动本地服务。
2. 点击左侧“应用启动器”，点击“选择快捷方式”。
3. 在文件选择器中选择 Windows `.lnk` 或 `.url` 文件。每次选择一个，导入后会复制到项目的本地数据目录。
4. 点击单条记录的“启动”，或点击页面右上角“全部启动”并行启动所有已添加的快捷方式。
5. 可使用刷新按钮重新读取列表，也可以删除不再使用的快捷方式。

快捷方式启动由 Vite 本地接口调用 PowerShell `Start-Process -FilePath` 执行。服务会等待 PowerShell 子进程返回；如果快捷方式不存在、文件类型不支持或 Windows 启动失败，页面会显示错误。当前功能仅支持 Windows，浏览器本身不能直接执行本地文件。

### 修改本地端口

1. 打开侧边栏底部的“设置”。
2. 选择“启动设置”。
3. 在“绑定端口”中输入 `1024-65535` 之间的整数并保存。
4. 页面收到保存结果后会调用重启脚本；新服务就绪时自动打开 `http://127.0.0.1:<新端口>/`。

端口保存接口会拒绝已经被其他程序占用的端口。运行中的服务不会原地换端口，而是在响应保存成功后调用项目根目录的重启脚本。

服务未启动或未启用开机自启动时，可以直接双击项目根目录的 `start.cmd`，整个过程不会显示 CMD 窗口。未保存过端口时使用默认端口 `5180`；已有端口配置时使用已保存端口。需要停止服务时双击 `end.cmd`。脚本只停止当前项目的 Vite 服务，不会影响其他项目的 Node.js 进程。`restart-workbench.vbs` 和 `restart-workbench.cmd` 是由启动流程及端口切换使用的内部脚本。

工作区注册表、提示词、网址、书籍、API Key 密文及应用快捷方式都保存在项目的 `.workbench-data/`，不再依赖浏览器端口来源。修改端口并重启后，可以直接打开原有工作区和数据。

全新安装只读取当前安装目录的 `.workbench-data`，不会读取或迁移浏览器里其他版本留下的 `localStorage`。从旧版本升级时，请先在旧版本中导出加密工作区配置，再在新版本的创建工作区页面选择“导入已有配置”。

### 本地服务接口

| 接口 | 方法 | 用途 |
| --- | --- | --- |
| `/api/server` | `GET` | 读取配置端口、当前活动端口和重启状态 |
| `/api/server` | `POST` | 保存绑定端口并检查端口占用 |
| `/api/server/stop` | `POST` | 关闭当前本地服务 |
| `/api/storage` | `GET` | 读取当前安装目录中的工作区配置 |
| `/api/storage/registry` | `PUT` | 保存工作区注册表 |
| `/api/storage/workspaces/:id/:key` | `PUT` | 保存工作区提示词、网址、书籍元数据或 API Key 密文 |
| `/api/storage/import` | `PUT` | 原子导入工作区注册表和配置数据 |
| `/api/storage/security` | `PUT` | 原子更新密码校验材料和 API Key 密文 |
| `/api/books/:workspace/:fileId` | `GET/HEAD/PUT/DELETE` | 读取、检查、保存或删除书籍文件 |
| `/api/startup` | `GET` | 读取 Windows 开机自启动状态 |
| `/api/startup` | `POST` | 开启或关闭 Windows 开机自启动 |
| `/api/shortcuts` | `GET/POST` | 读取或导入当前工作区快捷方式 |
| `/api/shortcuts/:id/launch` | `POST` | 启动本机快捷方式 |
| `/api/shortcuts/:id` | `DELETE` | 删除快捷方式副本和索引 |
| `/api/system` | `GET` | 读取当前本机用户名，用于概述页问候语 |

## 本地安全模型

工作台密码用于派生 API Key 加密密钥，密码本身不会保存：

1. 首次设置密码时生成 16 字节随机盐值，并生成密码验证材料。
2. 使用 PBKDF2-SHA-256、250,000 次迭代派生 256 位密钥材料。
3. 每个 API Key 使用独立的 12 字节随机 IV，通过 AES-256-GCM 加密。
4. 本地配置文件只保存 API Key 的密文、IV、名称、服务商、请求地址和更新时间。
5. 解密后的 API Key 只存在当前页面内存中；刷新页面后必须重新解锁，已显示的值也会清除。

这适合本机个人使用，但不能替代操作系统凭据保险库。若设备已被恶意软件控制、浏览器被完全接管或工作台密码泄露，敏感数据仍可能暴露。

## 数据位置和备份

升级 Release 时，先退出工作台并备份整个 `.workbench-data`。把新版程序文件覆盖到原目录，但不要删除或替换 `.workbench-data`。如果移动到另一台电脑，应同时复制该目录；工作区密码仍然是解锁 API Key 密文所必需的。

### 项目目录

| 路径 | 内容 |
| --- | --- |
| `.workbench-data/shortcuts.json` | 快捷方式名称、扩展名、文件名和本地索引 |
| `.workbench-data/shortcuts/` | 导入的 `.lnk` / `.url` 文件副本 |
| `.workbench-data/startup.json` | Windows 开机自启动状态 |
| `.workbench-data/server.json` | 本地服务绑定主机和端口，未配置时默认端口为 5180 |
| `.workbench-data/workbench.json` | 工作区注册表、提示词、网址、书籍元数据和 API Key 密文 |
| `.workbench-data/workspaces/{workspaceId}/books/` | 导入的个人书籍文件 |
| `.workbench-data/start-workbench.vbs` | 按当前配置端口隐藏启动本地服务的脚本，仅在启用时存在 |

`.workbench-data/` 已加入 `.gitignore`，不会被默认提交到 Git。备份工作台时请完整备份该目录；不要把其中的 API Key 密文或导出的配置随意上传。

开机启动快捷方式位于 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\PersonalWorkbench.lnk`。修改端口时会同步更新启动脚本；项目目录或 Node.js 安装位置变化后，请先关闭再重新开启该选项，以刷新启动项路径。

程序不会读取或清理旧版浏览器 `localStorage`。旧数据需要时应从旧版本导出加密配置，再导入当前版本。

```text
cc_workbench/
├── src/
│   ├── main.jsx       # React 状态、页面模块、表单和加密逻辑

├── package-lock.json  # npm 依赖锁定文件
├── RELEASE_NOTES.md   # 当前版本发布说明

```

## 开发协作约定

后续修改由用户手动验证。除非用户明确要求，协作会话不要自行运行构建、测试、浏览器自动化或功能回归，也不要创建测试工作区、修改真实端口/启动项或启动本机软件。

未经过用户验证的改动必须明确标记为“等待用户检查”。只有用户明确要求时才运行验证命令、提交 Git 或创建版本。
