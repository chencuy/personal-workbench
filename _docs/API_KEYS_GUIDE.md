# API Keys 管理指南

## 功能概述

API Keys 模块是一个本地化的密钥管理工具，使用 AES-256-GCM 加密算法保护敏感信息。所有密钥数据按工作区隔离存储，仅在本机使用，不会上传到云端。

---

## 安全模型

### 加密技术

| 组件 | 技术方案 |
|------|---------|
| 密钥派生 | PBKDF2-SHA-256，250,000 次迭代 |
| 加密算法 | AES-256-GCM |
| 初始化向量 | 每个密钥独立的 12 字节随机 IV |
| 盐值 | 16 字节随机盐，工作区创建时生成 |

### 加密流程

1. **工作区创建**：生成 16 字节随机盐值
2. **密钥派生**：使用 PBKDF2 从密码派生 256 位主密钥
3. **API Key 保存**：
   - 生成 12 字节随机 IV
   - 使用 AES-256-GCM 加密 API Key
   - 保存密文、IV 和认证标签
4. **解密**：输入工作区密码 → 派生密钥 → 解密 API Key

### 安全特性

✅ **密码不存储**：工作区密码明文不会写入任何文件  
✅ **独立 IV**：每个 API Key 使用独立随机 IV  
✅ **认证加密**：GCM 模式提供完整性验证  
✅ **内存隔离**：解密后的 API Key 仅存在页面内存中  
✅ **刷新清除**：刷新页面后需要重新解锁工作区  

⚠️ **安全边界**：
- 本方案适合本机个人使用
- 不能抵御操作系统级恶意软件
- 不能替代操作系统凭据保险库
- 工作区密码泄露会导致所有 API Key 泄露

## 快速开始

### 第一次添加 API Key

**操作步骤：**

1. 点击左侧导航栏"**API Keys**"
2. 点击页面右上角"**添加 API Key**"
3. 填写以下字段：
   - **名称**（必填）：用于识别，例如"OpenAI 生产环境"
   - **服务商**（必填）：例如"OpenAI"、"Anthropic"、"阿里云"
   - **API Key**（必填）：从服务商获取的密钥
   - **请求地址**（必填）：API 端点，必须以 `http://` 或 `https://` 开头
4. 点击"**加密保存**"
5. 系统会立即加密 API Key 并保存到本地

**示例配置：**

| 名称 | 服务商 | API Key | 请求地址 |
|------|--------|---------|----------|
| OpenAI Production | OpenAI | sk-proj-... | https://api.openai.com/v1 |
| Anthropic Claude | Anthropic | sk-ant-... | https://api.anthropic.com/v1 |
| 本地 LLM | Ollama | 无需密钥 | http://localhost:11434/api |

## 核心功能

### 1. 查看 API Keys

**列表显示：**
- **名称**：完整显示
- **服务商**：完整显示
- **API Key**：默认掩码显示（例如：`sk-pro••••••••••••••••••`）
- **请求地址**：完整显示
- **操作按钮**：显示/隐藏、编辑、删除

**API Key 掩码规则：**
- 显示前 6 个字符（如果长度 < 6，显示前一半）
- 中间部分替换为 20 个 `•`
- 不显示后缀

---

### 2. 显示/隐藏 API Key

**操作步骤：**

1. 找到需要查看的 API Key 记录
2. 点击行末的"**👁️**"（眼睛）按钮
3. 系统会在内存中解密并显示完整 API Key
4. 再次点击隐藏

**安全提示：**
- 显示的 API Key 仅存在于当前页面
- 刷新页面后需要重新解锁工作区
- 不建议在公共场所显示 API Key
- 显示后建议尽快复制并隐藏

---

### 3. 编辑 API Key

**操作步骤：**

1. 点击 API Key 记录行末的"**✏️**"（编辑）按钮
2. 系统会在内存中解密原 API Key 并填充到表单
3. 修改任意字段（名称、服务商、API Key、请求地址）
4. 点击"**保存**"
5. 系统会使用**新的随机 IV** 重新加密 API Key

**编辑场景：**
- 更新过期的 API Key
- 修正错误的请求地址
- 重命名或更改服务商标识
- 切换生产环境和测试环境

⚠️ **注意**：编辑时会重新加密，即使 API Key 本身没有修改。

---

### 4. 删除 API Key

**操作步骤：**

1. 点击 API Key 记录行末的"**🗑️**"（删除）按钮
2. 系统会立即删除该记录（**不可恢复**）
3. 密文、IV 和元数据会一并删除

⚠️ **警告**：
- 删除操作无法撤销
- 删除后无法恢复原 API Key
- 建议删除前先复制 API Key 到安全位置

---

### 5. 复制 API Key

**方法 1：从列表复制**
1. 点击"👁️"显示 API Key
2. 手动选中并复制完整密钥

**方法 2：从编辑窗口复制**
1. 点击"✏️"编辑
2. 在 API Key 输入框中全选并复制
3. 点击"取消"放弃编辑

## 与其他模块集成

### 配合 HTTP 客户端使用

HTTP 客户端可以直接使用 API Keys 模块中保存的密钥：

**操作步骤：**

1. 打开"**HTTP 客户端**"
2. 在"使用 API Key"下拉框中选择已保存的密钥
3. 点击"**使用 API Key**"按钮
4. 系统会自动：
   - 解密 API Key
   - 在 Headers 中添加 `Authorization: Bearer <解密后的密钥>`
   - 不在界面明文显示
5. 发送 HTTP 请求测试 API

**安全特性：**
- 密钥解密后直接填充到 Headers
- HTTP 客户端不会明文显示 API Key
- 请求历史不会保存 API Key 明文

**详细说明**：参见 [HTTP_CLIENT_GUIDE.md](HTTP_CLIENT_GUIDE.md)

## 数据管理

### 存储位置

API Keys 数据保存在：
```
.workbench-data/workbench.json
```

**存储格式：**
```json
{
  "workspaces": {
    "<workspace-id>": {
      "apiKeys": [
        {
          "id": "生成的唯一 ID",
          "name": "名称（明文）",
          "provider": "服务商（明文）",
          "encryptedKey": "加密后的 API Key（Base64）",
          "iv": "初始化向量（Base64）",
          "url": "请求地址（明文）",
          "updatedAt": "更新时间戳"
        }
      ]
    }
  }
}
```

**明文字段：**
- `name`（名称）
- `provider`（服务商）
- `url`（请求地址）
- `updatedAt`（更新时间）

**加密字段：**
- `encryptedKey`（API Key 密文）
- `iv`（每条记录独立的初始化向量）

### 备份与导出

**导出工作区配置：**

1. 进入"**设置 > 数据管理**"
2. 点击"**导出工作区配置**"
3. 系统会生成加密的 JSON 文件，包含：
   - 工作区元数据
   - 加密的 API Keys
   - 其他模块数据（提示词、网址等）

**导出文件安全：**
- 整个配置文件使用工作区密钥加密
- 不包含密码明文
- 不包含 API Key 明文
- 必须输入原工作区密码才能导入

**备份建议：**
- 定期备份 `.workbench-data/` 目录
- 导出工作区配置到云盘（加密安全）
- 升级版本前先备份数据
- 妥善保管工作区密码

---

### 导入配置

**场景**：迁移到新设备或恢复备份

**操作步骤：**

1. 在新设备的创建工作区页面选择"**导入已有配置**"
2. 或在已有工作区的"**设置 > 数据管理**"选择"**导入配置**"
3. 上传之前导出的 JSON 文件
4. 输入**原工作区密码**
5. API Keys 会自动恢复并重新加密

⚠️ **重要**：
- 导入时必须输入**正确的原工作区密码**
- 密码错误会导致解密失败
- 导入成功后，API Keys 会使用新工作区的密钥重新加密

## 修改工作区密码

### 自动重新加密

当修改工作区密码时，系统会自动重新加密所有 API Keys：

**流程：**

1. 进入"**设置 > 密码与安全**"
2. 输入当前密码
3. 输入新密码（至少 8 位）
4. 点击"**修改密码**"
5. 系统会：
   - 使用旧密码派生的密钥解密所有 API Keys
   - 使用新密码派生的密钥重新加密所有 API Keys
   - 生成新的随机 IV
   - 更新密码验证材料

**安全保障：**
- 整个过程在内存中完成
- 旧密钥和新密钥不会写入磁盘
- 失败时会回滚到原状态
- 成功后旧密码立即失效

## 使用场景

### 场景 1：管理多个 AI 服务密钥

**需求**：同时使用 OpenAI、Anthropic、Google AI

**方案：**

1. 为每个服务添加一条 API Key：
   - OpenAI Production（生产环境）
   - OpenAI Staging（测试环境）
   - Anthropic Claude
   - Google Gemini
2. 使用时从列表选择对应服务
3. 在 HTTP 客户端或外部工具中使用

---

### 场景 2：区分生产和测试环境

**需求**：避免在生产环境误用测试密钥

**方案：**

1. 添加两条记录：
   - "OpenAI Production"（生产环境密钥）
   - "OpenAI Staging"（测试环境密钥）
2. 在名称中明确标注环境
3. 请求地址也分别配置
4. 使用时仔细核对名称

---

### 场景 3：团队协作（多工作区）

**需求**：个人项目和公司项目使用不同密钥

**方案：**

1. 创建两个工作区：
   - "个人项目"工作区
   - "公司项目"工作区
2. 在各自工作区中添加对应的 API Keys
3. 切换工作区时需要输入对应密码
4. 密钥完全隔离，互不影响

---

### 场景 4：本地 LLM 集成

**需求**：使用 Ollama、LM Studio 等本地模型

**方案：**

1. 添加 API Key：
   - **名称**：本地 Ollama
   - **服务商**：Ollama
   - **API Key**：留空或填写"无需密钥"
   - **请求地址**：`http://localhost:11434/api`
2. 在 HTTP 客户端中测试本地 API
3. 不需要真正的密钥，但可以统一管理端点

## 最佳实践

### 1. 命名规范

**好的命名示例：**
- ✅ "OpenAI Production - GPT-4"
- ✅ "Anthropic Staging - Claude 3"
- ✅ "Azure OpenAI - 东亚区"

**不好的命名示例：**
- ❌ "key1"
- ❌ "test"
- ❌ "aaa"

**命名建议：**
- 包含服务商名称
- 注明环境（生产/测试/开发）
- 可选：注明用途或项目名

---

### 2. 密钥轮换

**定期更换密钥：**

1. 在服务商平台生成新密钥
2. 在工作台中编辑对应记录
3. 更新 API Key 字段
4. 在服务商平台撤销旧密钥
5. 测试新密钥是否正常工作

**建议频率：**
- 生产环境：每 3-6 个月
- 测试环境：每 6-12 个月
- 泄露风险：立即更换

---

### 3. 密码管理

**工作区密码要求：**
- ✅ 至少 8 位
- ✅ 包含大小写字母、数字、符号
- ✅ 不与其他账户密码相同
- ✅ 定期更换（建议每年一次）

**密码安全建议：**
- 使用密码管理器（1Password、Bitwarden）
- 不要在代码或文档中硬编码
- 不要通过即时通讯工具发送
- 忘记密码无法恢复，请妥善保管

---

### 4. 定期备份

**备份清单：**
- [ ] `.workbench-data/` 完整目录
- [ ] 导出的加密工作区配置
- [ ] 工作区密码（存储在密码管理器）
- [ ] 服务商平台的备用密钥

**备份频率：**
- 添加或修改 API Key 后立即备份
- 定期（每月）导出工作区配置
- 升级版本前必须备份

## 常见问题

### Q1: 忘记工作区密码怎么办？

**A**: 当前版本**无法恢复**密码或 API Keys。

**预防措施：**
- 使用密码管理器保存工作区密码
- 定期导出加密配置到安全位置
- 在 API Keys 服务商平台保留备用密钥

**如果已忘记：**
- 创建新工作区
- 重新从服务商平台获取新 API Keys
- 旧工作区的数据无法恢复

---

### Q2: API Key 解密失败？

**A**: 可能原因：

1. **工作区密码已修改**
   - 解决：输入正确的新密码重新解锁

2. **数据损坏**
   - 解决：从备份恢复 `.workbench-data/`

3. **导入配置时密码错误**
   - 解决：使用原工作区密码导入

4. **浏览器不支持 Web Crypto API**
   - 解决：使用现代浏览器（Chrome 87+、Firefox 91+、Edge 87+）

---

### Q3: 可以跨工作区共享 API Key 吗？

**A**: 不能直接共享，但可以通过以下方式：

**方法 1：手动复制**
1. 在源工作区显示 API Key
2. 复制完整密钥
3. 切换到目标工作区
4. 添加新 API Key 并粘贴

**方法 2：导出导入**
1. 导出源工作区配置
2. 在目标工作区导入
3. API Keys 会随配置一起导入

---

### Q4: HTTP 客户端中使用 API Key 安全吗？

**A**: 相对安全，但有注意事项：

**安全特性：**
- ✅ API Key 解密后直接填充到 Headers
- ✅ 不在界面明文显示
- ✅ 请求历史不保存 API Key 明文

**注意事项：**
- ⚠️ 请求发送到真实服务器（检查 URL）
- ⚠️ 避免在公共场所使用
- ⚠️ 使用测试环境密钥进行测试

---

### Q5: 可以导出未加密的 API Keys 吗？

**A**: 不能，也不建议。

**原因：**
- 导出未加密数据会破坏安全模型
- 明文存储在磁盘上容易泄露
- 云同步工具可能备份到公共云

**替代方案：**
- 导出加密的工作区配置（安全）
- 在服务商平台查看原始密钥
- 使用密码管理器单独保存密钥副本

---

### Q6: 多设备同步怎么办？

**A**: 当前版本不支持自动同步，但可以手动迁移：

**方案 1：导出导入**
1. 在设备 A 导出工作区配置
2. 通过云盘或 U 盘传输到设备 B
3. 在设备 B 导入配置

**方案 2：备份目录同步**
1. 将 `.workbench-data/` 复制到设备 B
2. 确保两个设备的工作台版本一致
3. 在设备 B 启动工作台并解锁

⚠️ **注意**：
- 不要同时在两台设备上修改
- 修改后记得同步到另一台设备
- 云同步工具可能导致配置冲突
